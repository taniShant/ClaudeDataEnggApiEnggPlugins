# Code Generation Rules - Spring Boot 3 + Java 21

## Overview

This document defines the authoritative rules for generating production-ready Java code from OpenAPI 3.x specifications. Only OpenAPI 3.x is supported — RAML specifications are not accepted.

---

## Clean Code Standards

These rules apply to ALL generated Java source. Violations are flagged by Phase 5b and daf-validation-agent Red Flag #21.

### Method Quality

| Rule | Limit | Action when exceeded |
|---|---|---|
| Business logic method length | 30 lines | Extract cohesive blocks into `private` methods with descriptive names |
| Parameters per method | 5 | Introduce a request/context object |
| Cyclomatic complexity per method | 5 branches | Extract each branch into a named private method |

**Example — over-complex method that must be decomposed:**
```java
// ❌ BAD: 60-line method with 8 branches inline
public RestResponse processApplication(Request request) { ... }

// ✅ GOOD: orchestration only, branches extracted
public RestResponse processApplication(Request request) {
    ApplicationRequest appRequest = extractAndValidate(request);
    CustomerProfile profile = retrieveCustomerProfile(appRequest.getCustomerId());
    EligibilityResult eligibility = assessEligibility(profile);
    return eligibility.isEligible()
        ? submitApplication(appRequest, profile)
        : buildIneligibleResponse(eligibility);
}
```

### Use-Case Naming

Service method names MUST express business intent — not CRUD operations.

| ❌ FORBIDDEN (generic CRUD) | ✅ REQUIRED (business intent) |
|---|---|
| `save(request)` | `submitApplication(request)` |
| `get(request)` | `retrieveCustomerProfile(request)` |
| `update(request)` | `updateContactPreferences(request)` |
| `delete(request)` | `cancelDirectDebit(request)` |
| `find(request)` | `searchEligibleProducts(request)` |
| `create(request)` | `registerDevice(request)` |

The method name should read like a sentence that describes what a user is doing.

### No Magic Values

```java
// ❌ BAD: magic string and magic number
if ("C01".equals(segmentCode) && attempts > 3) { ... }

// ✅ GOOD: named constants
if (EligibilityConstants.SIMPLE_MANDATE_GROUP.equals(segmentCode)
        && attempts > EligibilityConstants.MAX_RETRY_ATTEMPTS) { ... }
```

- No string literals in business logic — use `{Feature}Constants` class or `ErrorCodes` enum
- No numeric literals except `0`, `1`, `-1` — use named constants
- Constants class: `public final class {Feature}Constants { private {Feature}Constants() {} ... }`

### Logging Levels

Apply consistently across ALL layers:

| Level | When to use | Example |
|---|---|---|
| `log.info()` | Method entry, successful operation exit | `"Retrieving customer profile for customerId: {}"` |
| `log.warn()` | Recoverable business rule violation | `"Customer not eligible: segmentCode {} not in allowed set"` |
| `log.error()` | Exception caught, downstream failure | `"Failed to call CustomerEnquiry API: {}"` |

Never use `log.debug()` in generated production code — it is filtered at runtime and creates noise.

### Single Responsibility

- Each `ServiceImpl` handles exactly ONE business domain feature (eligibility, submit, content, etc.)
- Each `GatewayImpl` calls exactly ONE downstream API endpoint group
- Mapper classes contain ONLY field-mapping logic — no if/else business decisions
- Constants classes contain ONLY `public static final` values — no methods

## Model Generation

### Request/Response DTOs

**Rule 1.1**: All request models go in `model/request/`

```
com.example.api.model.request
├── CreateUserRequest.java
├── UpdateUserRequest.java
└── SearchUsersRequest.java
```

**Rule 1.2**: All response models go in `model/response/`

```
com.example.api.model.response
├── UserResponse.java
├── UserListResponse.java
└── ErrorResponse.java
```

**Rule 1.3**: Use Java Records for all DTOs — NO Lombok

🔴 **MANDATORY**: All request and response DTOs MUST be Java Records (Java 16+, standard in Java 21). Do NOT use Lombok (`@Data`, `@Builder`, `@NoArgsConstructor`, `@AllArgsConstructor`) on DTO classes.

```java
// ✅ CORRECT: Java Record (replaces @Data/@Builder/@NoArgsConstructor/@AllArgsConstructor)
public record UserResponse(
    Integer id,
    String email,
    String name
) {}
```

**Why Records?**
- Java 21 built-in — no Lombok dependency required
- Immutable by default: all fields are `final`, no setters
- Compiler-generated: canonical constructor, `equals()`, `hashCode()`, `toString()`, and accessors
- Jackson 2.12+ deserialises records automatically via the canonical constructor
- Shorter, cleaner code — less boilerplate than Lombok POJOs

**Accessor naming:** Records use `fieldName()` (not `getFieldName()`). When consuming generated DTOs, call `response.id()`, `response.email()` — not `response.getId()`.

**Jackson compatibility:** Spring Boot 3 ships with Jackson 2.14+ which deserialises records with no extra configuration. No `@JsonCreator` needed. If you need to rename a JSON property, use `@JsonProperty` on the record component:

```java
public record CreateUserRequest(
    @JsonProperty("full_name") String fullName,
    String email
) {}
```

**Null fields:** Declare the component type as nullable by convention; if using `spring-context` `@Nullable`, annotate the component:

```java
import org.springframework.lang.Nullable;

public record UserResponse(
    Integer id,
    String email,
    @Nullable String nickname   // explicitly nullable
) {}
```

**Rule 1.3b**: Record instantiation replaces the builder pattern

Because records are immutable, use the canonical constructor directly:

```java
// Creating a record instance (replaces Builder.builder().x(...).build())
UserResponse response = new UserResponse(1, "john@example.com", "John Doe");

// In tests — use the canonical constructor
CreateUserRequest request = new CreateUserRequest("John Doe", "john@example.com", 30);
```

**Rule 1.3c**: Nested records

Nested DTOs are also records:

```java
public record CreateOrderRequest(
    String customerId,
    List<OrderLineRequest> lines,
    AddressRequest deliveryAddress
) {}

public record OrderLineRequest(
    String productId,
    Integer quantity
) {}

public record AddressRequest(
    String street,
    String city,
    String postcode
) {}
```

**Rule 1.3d**: Collections and maps in records

```java
public record SearchResponse(
    List<UserResponse> users,         // List field
    Map<String, String> metadata,     // Map field
    int totalCount
) {}
```

**Rule 1.3e**: Records with enum fields

```java
public record OrderResponse(
    String orderId,
    OrderStatus status,
    BigDecimal total
) {}
```

**Rule 1.4**: STRICTLY NO jakarta.validation Annotations

🔴 **MANDATORY**: DO NOT import or use ANY annotations from `jakarta.validation` package:
- ❌ DO NOT use: `@NotNull`, `@NotBlank`, `@Email`, `@Min`, `@Max`, `@Pattern`, `@Size`, `@Valid`
- ❌ DO NOT import: `jakarta.validation.*`
- ❌ DO NOT depend on: `jakarta.validation:jakarta.validation-api`

**Why:** 
1. Validation is performed by the gateway/frontend application before requests reach this API
2. Generated DTOs are plain data carriers — zero validation logic
3. Field-level validation annotations create false security — the real validation happens upstream

**CORRECT Pattern:**
```java
// ✅ CORRECT: Java Record — no validation annotations
public record CreateUserRequest(
    String name,
    String email,
    Integer age
) {}

// ❌ WRONG: Never do this
public record CreateUserRequest(
    @NotNull(message = "name required")  // ❌ FORBIDDEN
    @Email(message = "invalid email")    // ❌ FORBIDDEN
    String name,
    String email
) {}
```

**Rule 1.5**: Map nullable fields in specs

Spec: nullable property → annotate the record component with `@Nullable`:

```java
import org.springframework.lang.Nullable;

public record UserResponse(
    Integer id,
    String email,
    @Nullable String nickname
) {}
```

**Rule 1.6**: Handle arrays and collections

Spec: `array of string` → Java: `List<String>`  
Spec: `array of object` → Java: `List<ModelName>`

**Rule 1.7**: Handle enums

Spec enums become Java enums:

```yaml
# OAS
status:
  type: string
  enum: [active, inactive, pending]
```

```java
// Java
public enum Status {
    ACTIVE,
    INACTIVE,
    PENDING
}
```

### JPA Entities (Database Layer Only)

**Rule 1.8**: Entity classes in `model/entity/`

JPA entities CANNOT be records because JPA requires mutable objects with a no-arg constructor. Use traditional classes with Lombok for entities only:

```java
@Entity
@Table(name = "users")
@Data
@NoArgsConstructor
@AllArgsConstructor
public class UserEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;
    
    @Column(nullable = false, unique = true)
    private String email;
    
    @Column(name = "full_name")
    private String name;
}
```

**Lombok is PERMITTED for JPA entities only.** All other model classes (request DTOs, response DTOs) MUST be records.

**Rule 1.9**: Always use `@Column` for explicit mapping

```java
@Column(name = "db_column_name", nullable = false, unique = true)
```

**Rule 1.10**: Use `@CreatedDate`, `@LastModifiedDate` for timestamps

```java
@CreatedDate
@Column(nullable = false, updatable = false)
private LocalDateTime createdAt;

@LastModifiedDate
@Column(nullable = false)
private LocalDateTime updatedAt;
```

## Controller Generation

**Rule 2.1**: Controllers in `controller/` package

```java
import com.barclays.api.bap.bld.lib.common.response.Response;
import com.barclays.api.bap.bld.lib.payload.response.ResponseHttpStatus;
import com.barclays.api.bap.bld.lib.payload.response.RestResponse;
import {basePackage}.context.ApiContext;

@RestController
@RequestMapping("/api/v1/users")
@RequiredArgsConstructor
public class UserController {
    private final UserService userService;
    
    @PostMapping
    public Response createUser(
        ApiContext apiContext,
        @RequestBody CreateUserRequest request) {
        return RestResponse
                    .assemble()
                    .build(ResponseHttpStatus.CREATED, userService.create(apiContext, request));
    }
}
```

**Rule 2.2**: Use constructor injection via Lombok `@RequiredArgsConstructor`

```java
@RequiredArgsConstructor
public class UserController {
    private final UserService userService;
    // No @Autowired, no setters
}
```

**Rule 2.2b**: Access record fields using accessor methods (not getters)

When reading fields from a record DTO inside a controller or service, use the accessor method (field name, no `get` prefix):

```java
// ✅ CORRECT: Record accessor — no "get" prefix
LOGGER.info("Creating user: {}", request.name());
String email = request.email();

// ❌ WRONG: Getter-style — records do not have getters
LOGGER.info("Creating user: {}", request.getName());  // compile error
```

**Rule 2.3**: HTTP method mapping

| Spec | HTTP | Annotation |
|------|------|-----------|
| Create | POST | `@PostMapping` |
| Retrieve | GET | `@GetMapping` |
| Update | PUT/PATCH | `@PutMapping` / `@PatchMapping` |
| Delete | DELETE | `@DeleteMapping` |

**Rule 2.4**: Request body validation

```java
import com.barclays.api.bap.bld.lib.common.response.Response;

@PostMapping
public Response create(
    @RequestBody @Valid CreateUserRequest request) {
    // @Valid triggers validation
}
```

**Rule 2.5**: Response status codes

- POST (create): `HttpStatus.CREATED` (201)
- GET: `HttpStatus.OK` (200)
- PUT/PATCH: `HttpStatus.OK` (200)
- DELETE: `HttpStatus.NO_CONTENT` (204)
- Errors: Use appropriate status from spec

**Rule 2.6**: Path and query parameters

```java
import com.barclays.api.bap.bld.lib.common.response.Response;
import com.barclays.api.bap.bld.lib.payload.response.ResponseHttpStatus;
import com.barclays.api.bap.bld.lib.payload.response.RestResponse;

@GetMapping("/{id}")
public Response getUser(
    @PathVariable Integer id) {
        return RestResponse
                    .assemble()
                    .build(ResponseHttpStatus.OK, userService.findById(id));
}

@GetMapping
public Response search(
    @RequestParam(required = false) String email,
    @RequestParam(required = false, defaultValue = "10") Integer limit) {
    return RestResponse
                    .assemble()
                    .build(ResponseHttpStatus.OK, userService.search(email, limit));
}
```

**Rule 2.7**: SDK3 Integration (MANDATORY — ALL controllers use this pattern)

All controller responses MUST use `RestResponse.assemble().build()`:

```java
import com.barclays.api.bap.bld.lib.common.response.Response;
import com.barclays.api.bap.bld.lib.payload.response.RestResponse;
import com.barclays.api.bap.bld.lib.payload.response.ResponseHttpStatus;
import {basePackage}.context.ApiContext;

@RestController
@RequestMapping("/api/v1/users")
@RequiredArgsConstructor
public class UserController {
    private final UserService userService;
    private static final Logger LOGGER = LogFactory.getLogger(UserController.class);
    
    @PostMapping
    public Response createUser(
        ApiContext apiContext,
        @RequestBody CreateUserRequest request) {
        LOGGER.info("Creating user from request");
        UserResponse user = userService.create(apiContext, request);
        return RestResponse.assemble().build(ResponseHttpStatus.CREATED, user);
    }
    
    @GetMapping("/{id}")
    public Response getUser(ApiContext apiContext, @PathVariable Integer id) {
        LOGGER.info("Fetching user with id: {}", id);
        UserResponse user = userService.findById(apiContext, id);
        return RestResponse.assemble().build(ResponseHttpStatus.OK, user);
    }
}
```

**Key Pattern:**
- `ApiContext apiContext` MUST be the first parameter on every controller method
- Use `RestResponse.assemble().build(ResponseHttpStatus.STATUS, responseData)`
- ResponseHttpStatus options: `OK` (200), `CREATED` (201), `BAD_REQUEST` (400), etc.
- All responses automatically wrapped with metadata and correlation ID by SDK3
- Import: `com.barclays.api.bap.bld.lib.payload.response.RestResponse`
- Import: `com.barclays.api.bap.bld.lib.payload.response.ResponseHttpStatus`
- Import: `{basePackage}.context.ApiContext`

🔴 **CONTROLLER PROHIBITED PATTERNS:**

| Prohibited | Rule |
|---|---|
| `ResponseEntity` as method return type | Use `Response` from `com.barclays.api.bap.bld.lib.common.response` |
| `ResponseEntity.status(...).body(...)` | Use `RestResponse.assemble().build(ResponseHttpStatus.STATUS, data)` |
| `@Slf4j` or `org.slf4j.Logger` import | Use `LogFactory.getLogger(ClassName.class)` |
| `RestTemplate` or `WebClient` in any class | Use SDK3 `RestApiClient` |
| Any `@Configuration` class other than `ApplicationConfig` | SDK3 auto-configures everything else |

## Service Generation

**Rule 3.1**: Services in `service/` (interface) + `service/impl/` (implementation)

```java
// Interface
import {basePackage}.context.ApiContext;

public interface UserService {
    UserResponse create(ApiContext apiContext, CreateUserRequest request);
    UserResponse findById(ApiContext apiContext, Integer id);
    List<UserResponse> search(ApiContext apiContext, String email, Integer limit);
}

// Implementation
import com.barclays.api.bap.bld.lib.logging.LogFactory;
import com.barclays.api.bap.bld.lib.logging.Logger;
import {basePackage}.context.ApiContext;

@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {
    private final UserRepository repository;
    private final UserGateway userGateway;
    private static final Logger LOGGER = LogFactory.getLogger(UserServiceImpl.class);
    
    @Override
    public UserResponse create(ApiContext apiContext, CreateUserRequest request) {
        LOGGER.info("Creating user: {}", request.name());  // record accessor — no "get" prefix
        // Pass apiContext to gateway calls
        return userGateway.createUser(apiContext, request);
    }
}
```

**Rule 3.2**: Use constructor injection

```java
@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {
    private final UserRepository repository;
    private final PaymentGateway paymentGateway;
    // Dependencies injected via constructor
}
```

**Rule 3.2b**: Logging using SDK3 Framework (MANDATORY)

🔴 **DO NOT use `@Slf4j`** or `LoggerFactory.getLogger()` from SLF4j.

Use SDK3 LogFactory instead:

```java
// ✅ CORRECT: SDK3 Logging
@Service

public class UserServiceImpl implements UserService {
```

**Imports to use:**
```java
import com.barclays.api.bap.bld.lib.logging.LogFactory;

// NOT: import lombok.extern.slf4j.Slf4j;
```

## Gateway Generation

**Rule 4.1**: Gateways in `gateway/` (interface) + `gateway/impl/` (implementation)

```java
// Interface
import {basePackage}.context.ApiContext;

public interface PaymentGateway {
    PaymentResponse processPayment(ApiContext apiContext, PaymentRequest request);
    PaymentStatus checkStatus(ApiContext apiContext, String transactionId);
}

// Implementation (using SDK3 RestApiClient with PerfLogger + ApiContext + UriComponentsBuilder)
@Component
public class PaymentGatewayImpl implements PaymentGateway {
    private static final Logger LOGGER = LogFactory.getLogger(PaymentGatewayImpl.class);
    private static final PerfLogger PERFORMANCE_LOGGER = LogFactory.getPerfLogger(PaymentGatewayImpl.class);

    @Value("${downstream.payment.base-url:https://payment-api.internal}")
    private String baseUrl;
    
    private final RestApiClient restApiClient;

    public PaymentGatewayImpl(RestApiClient restApiClient) {
        this.restApiClient = restApiClient;
    }
    
    @Override
    public PaymentResponse processPayment(ApiContext apiContext, PaymentRequest request) {
        LOGGER.info("Calling external Payment API");
        PerfEvent perfEvent = PERFORMANCE_LOGGER.start("Invoking Payment API Call");
        HttpHeaders httpHeaders = assembleHeaders(apiContext);
        URI uri = UriComponentsBuilder.fromUriString(baseUrl + "/v1/process")
                .build()
                .toUri();
        
        try {
            PaymentResponse response = restApiClient.call(
                    RestClientHttpMethod.POST,
                    uri,
                    request,
                    httpHeaders,
                    PaymentResponse.class
            ).getBody();
            return response;
        } catch (Exception e) {
            LOGGER.error("Error calling Payment API at {}: {}", uri, e.getMessage(), e);
            throw new GatewayException("Failed to process payment: " + e.getMessage(), HttpStatus.BAD_GATEWAY, e);
        } finally {
            LOGGER.debug("End - Gateway call for processPayment");
            perfEvent.stop();
        }
    }

    private HttpHeaders assembleHeaders(ApiContext apiContext) {
        HttpHeaders httpHeaders = new HttpHeaders();
        httpHeaders.add("Correlation-ID", apiContext.getCorrelationId());
        httpHeaders.add("Authorization", apiContext.getAuthorization());
        return httpHeaders;
    }
}
```

**Rule 4.2**: Inject RestApiClient (SDK3 auto-configures)

```java
@Component
public class PaymentGatewayImpl implements PaymentGateway {
    private final RestApiClient restApiClient;
    
    // Constructor injection required (not @RequiredArgsConstructor)
    public PaymentGatewayImpl(RestApiClient restApiClient) {
        this.restApiClient = restApiClient;
    }
}
```

**Rule 4.2b**: Mandatory PerfLogger Usage

Every gateway method MUST measure performance:

```java
private static final Logger LOGGER = LogFactory.getLogger(PaymentGatewayImpl.class);
private static final PerfLogger PERFORMANCE_LOGGER = LogFactory.getPerfLogger(PaymentGatewayImpl.class);

@Override
public PaymentResponse processPayment(ApiContext apiContext, PaymentRequest request) {
    LOGGER.info("Starting payment processing");
    PerfEvent perfEvent = PERFORMANCE_LOGGER.start("Processing Payment");
    HttpHeaders httpHeaders = assembleHeaders(apiContext);
    URI uri = UriComponentsBuilder.fromUriString(baseUrl + "/v1/process")
            .build()
            .toUri();
    
    try {
        // Downstream API call
        PaymentResponse response = restApiClient.call(
                RestClientHttpMethod.POST,
                uri,
                request,
                httpHeaders,
                PaymentResponse.class).getBody();
        return response;

        LOGGER.error("Payment processing failed: {}", e.getMessage(), e);
        throw new GatewayException(...);
    } finally {
        LOGGER.debug("Completed payment processing");
        perfEvent.stop();  // MANDATORY: Always stop perf event
    }
}
```

**Rule 4.3**: Error handling with RestApiClient

All gateway methods MUST wrap downstream calls in try-finally blocks:

```java
@Component
public class PaymentGatewayImpl implements PaymentGateway {
    private static final Logger LOGGER = LogFactory.getLogger(PaymentGatewayImpl.class);
    private static final PerfLogger PERFORMANCE_LOGGER = LogFactory.getPerfLogger(PaymentGatewayImpl.class);

    @Value("${downstream.payment.base-url:https://payment-api.internal}")
    private String baseUrl;
    
    private final RestApiClient restApiClient;
    
    public PaymentGatewayImpl(RestApiClient restApiClient) {
        this.restApiClient = restApiClient;
    }
    
    @Override
    public PaymentResponse processPayment(ApiContext apiContext, PaymentRequest request) {
        LOGGER.info("Processing payment for order: {}", request.orderId());  // record accessor
        PerfEvent perfEvent = PERFORMANCE_LOGGER.start("Invoking Payment API Call");
        HttpHeaders httpHeaders = assembleHeaders(apiContext);
        URI uri = UriComponentsBuilder.fromUriString(baseUrl + "/v1/process")
                .build()
                .toUri();
        try {
            PaymentResponse response = restApiClient.call(
                    RestClientHttpMethod.POST,
                    uri,
                    request,
                    httpHeaders,
                    PaymentResponse.class
            ).getBody();
            LOGGER.debug("Payment API response received");
            return response;
        } catch (Exception e) {
            LOGGER.error("Error calling Payment API at {}: {}", uri, e.getMessage(), e);
            throw new GatewayException("Failed to process payment: " + e.getMessage(), HttpStatus.BAD_GATEWAY, e);
        } finally {
            LOGGER.debug("End - Gateway call for processPayment");
            perfEvent.stop();  // MANDATORY: Always stops performance timer
        }
    }

    private HttpHeaders assembleHeaders(ApiContext apiContext) {
        HttpHeaders httpHeaders = new HttpHeaders();
        httpHeaders.add("Correlation-ID", apiContext.getCorrelationId());
        httpHeaders.add("Authorization", apiContext.getAuthorization());
        return httpHeaders;
    }
}
```

**Key Pattern:**
- Use `RestApiClient.call(HttpMethod, URI, requestBody, headers)` instead of RestClient fluent API
- Always wrap in try-finally with PerfLogger
- Log entry, exit, and error cases
- Use `perfEvent.stop()` in finally block

**Method Signature Reference:**

| HTTP Method | Signature | Use Case |
|-------------|-----------|----------|
| GET | `.call(GET, uri, httpHeaders, responseType)` | Retrieve resource |
| POST | `.call(POST, uri, request, httpHeaders, responseType)` | Create new resource |
| PUT | `.call(PUT, uri, request, httpHeaders, responseType)` | Replace entire resource |
| PATCH | `.call(PATCH, uri, request, httpHeaders, responseType)` | Partial update resource |

- Always catch exceptions and throw GatewayException
- NEVER use `URI.create()` — always use `UriComponentsBuilder`
- NEVER use `headerMap.forEach(httpHeaders::add)` — always use `assembleHeaders(apiContext)`

### Gateway Tests

**Rule 5.4**: Use `@ExtendWith(MockitoExtension.class)` + `@Mock RestApiClient` for SDK3 gateway tests

🔴 **NEVER use `@RestClientTest` or `MockRestServiceServer` for SDK3 gateways.** SDK3 gateways use

**Rule 5.4a: `any()` vs `any(RestClientHttpMethod.class)` — MANDATORY**

| Argument position | Correct matcher | Wrong matcher |
|---|---|---|
| 1st (HTTP method) | `any(RestClientHttpMethod.class)` | `any()` ← causes stub mismatch |
| 2nd (URI) | `any()` or `anyString()` | — |
| 3rd (request body) | `any()` | — |
| 4th (headers/class) | `any()` or `eq(Response.class)` | — |
| Response type (last) | `eq({ResponseType}.class)` | `any()` ← too broad |

The overloaded `RestApiClient.call(...)` method takes `RestClientHttpMethod` as its first parameter.
Mockito cannot disambiguate between overloads when the first argument uses a raw `any()` matcher.
Always use `any(RestClientHttpMethod.class)` for the first parameter.

**Rule 5.4b: Read the actual gateway implementation before writing tests**

Before generating a gateway test, read the concrete `{Name}GatewayImpl.java` file to determine:
- The exact `restApiClient.call(...)` overload used (number of parameters)
- Whether the gateway uses 4-arg or 5-arg `call()` (some overloads omit the request body for GET)
- The exact response type class passed as the last argument
- Which fields of the response the gateway accesses (to write meaningful field-level assertions)

**Rule 5.5**: Test coverage requirements

- Happy path: mock returns valid `ResponseEntity` with non-null body; assert specific field values
- Exception path: mock throws `RuntimeException`; assert `GatewayException` is thrown with correct message
- Null-body path (where applicable): mock returns `ResponseEntity.ok(null)`; assert error handling
- Use `@BeforeEach` with `ReflectionTestUtils.setField` to inject `baseUrl` (not a Spring context test)
- Each test is independent — no shared mutable state between tests

```java
import com.barclays.api.bap.bld.lib.common.response.Response;
import com.barclays.api.bap.bld.lib.logging.LogFactory;
import com.barclays.api.bap.bld.lib.logging.Logger;
import com.barclays.api.bap.bld.lib.payload.response.Message;
import com.barclays.api.bap.bld.lib.payload.response.ResponseHttpStatus;
import com.barclays.api.bap.bld.lib.payload.response.RestResponse;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.ArrayList;
import java.util.List;

@RestControllerAdvice
public class GlobalExceptionHandler {

    private static final Logger LOGGER = LogFactory.getLogger(GlobalExceptionHandler.class);

    // Single error message
    @ExceptionHandler(ResourceNotFoundException.class)
    public Response handleNotFound(ResourceNotFoundException ex) {
        LOGGER.error("Resource not found: {}", ex.getMessage());
        Message errorMessage = Message.create(ex.getErrorCode(), ex.getErrorTitle());
        return RestResponse.assemble()
                .addErrorMessage(errorMessage)
                .build(ResponseHttpStatus.NOT_FOUND);
    }

    @ExceptionHandler(IllegalArgumentException.class)
    public Response handleBadRequest(IllegalArgumentException ex) {
        LOGGER.error("Bad request: {}", ex.getMessage());
        Message errorMessage = Message.create(ex.getErrorCode(), ex.getErrorTitle());
        return RestResponse.assemble()
                .addErrorMessage(errorMessage)
                .build(ResponseHttpStatus.BAD_REQUEST);
    }

    // Multiple error messages
    @ExceptionHandler(GatewayException.class)
    public Response handleGatewayException(GatewayException ex) {
        LOGGER.error("Gateway error: {}", ex.getMessage(), ex);
        List<Message> errorMessages = new ArrayList<>();
        errorMessages.add(Message.create("500", "Downstream service error"));
        errorMessages.add(Message.create(ex.getErrorCode(), ex.getErrorTitle()));
        return RestResponse.assemble()
                .addErrorMessages(errorMessages)
                .build(ResponseHttpStatus.INTERNAL_SERVER_ERROR);
    }

    @ExceptionHandler(Exception.class)
    public Response handleGeneral(Exception ex) {
        LOGGER.error("Unexpected error: {}", ex.getMessage(), ex);
        Message errorMessage = Message.create("500", "An unexpected error occurred");
        return RestResponse.assemble()
                .addErrorMessage(errorMessage)
                .build(ResponseHttpStatus.INTERNAL_SERVER_ERROR);
    }
}
```

**Key pattern rules:**
- Return type: `com.barclays.api.bap.bld.lib.common.response.Response` — NOT `ResponseEntity`
- Single error: `RestResponse.assemble().addErrorMessage(Message.create("...")).build(ResponseHttpStatus.STATUS)`
- Multiple errors: `RestResponse.assemble().addErrorMessages(List<Message>).build(ResponseHttpStatus.STATUS)`
- Always log with SDK3 `LogFactory.getLogger()` in `LOGGER.error()`

❌ **DO NOT**: Call getters on record fields (e.g. `request.getName()`)  
✅ **DO**: Call record accessors (e.g. `request.name()`) — records expose components directly, no `get` prefix

❌ **DO NOT**: Add jakarta.validation annotations to DTOs (records or otherwise)  
✅ **DO**: Records are plain data carriers — zero validation logic
