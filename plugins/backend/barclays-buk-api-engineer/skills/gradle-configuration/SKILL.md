# Skill: Gradle Configuration — Barclays SDK3 + Spring Boot 3 + Java 21

## When to Use This Skill

This skill provides **reference documentation for Gradle configuration**. It shows what's included in the template files located at `plugins/api-engineer/templates/`.

**For generation:** Use this skill when you need to understand what each Gradle file contains. During actual project generation (Phase 1), copy template files directly from `templates/` directory instead of generating from scratch.

**Template files cover:**
- Gradle 8.13 (required)
- Spring Boot 3.x
- Java 21
- Barclays SDK3 (version 1.12.007)
- Organization Nexus repositories
- Organization plugins (bap-bld-lib, bap-bld-lib-kotlin-int-test-gradle-plugin)

## Critical Rule

**All Gradle configuration files MUST be copied from `templates/` directory — do NOT generate from scratch.** This skill contains reference documentation showing what the templates contain. During Phase 1 generation, copy template files verbatim from:
- `templates/settings.gradle`
- `templates/gradle-properties`
- `templates/build-root.gradle`
- `templates/buildSrc-build.gradle`
- `templates/checkstyle.xml`
- `templates/gradle-wrapper.properties`
- `templates/mutation.gradle`

Replace only the explicitly marked substitution placeholders: `{VERSION}`, `{ARTIFACT_ID}`, `{IMPLEMENTATION_TITLE}`, `{basePackage}`, `{AppName}`. No other modifications.

## Quick Start

Configure Gradle for a new SDK3 project:

1. Copy all template files from `templates/` directory verbatim
2. Replace ONLY these placeholders: `{VERSION}`, `{ARTIFACT_ID}`, `{IMPLEMENTATION_TITLE}`, `{basePackage}`, `{AppName}`
3. Do NOT generate Gradle files from scratch — always copy from templates

```groovy
// Example: settings.gradle placeholder replacement
rootProject.name = '{ARTIFACT_ID}'  // → rootProject.name = 'my-service'
```

## CRITICAL: SDK3 Dependency Management

### Why Only 3 Explicit Dependencies?

The SDK3 BOM (Bill of Materials) automatically provides all transitive dependencies. You DO NOT need to explicitly import:
- ❌ `com.barclays.api:bap-bld-lib-logging` (provided transitively)
- ❌ `com.barclays.api:bap-bld-lib-common` (provided transitively)
- ❌ `com.barclays.api:bap-bld-lib-payload` (provided transitively)
- ❌ `com.barclays.api:bap-bld-lib-restclient` (provided transitively)
- ❌ `com.barclays.api:bap-bld-lib-health` (provided transitively)

**The 3 core modules** (`request-validator`, `restapi`, `meshconnector`) pull in all others via the SDK3 platform BOM.

**DO NOT add redundant explicit dependencies** — this causes version conflicts and bloats the final JAR.

### Why Bean Implementations Are Provided Automatically

Once you create a bean of type `ExternalApiInitializer` or `InternalApiInitializer` in `ApplicationConfig.java`:

✅ **SDK3 provides default beans automatically:**
- `LogFactory` — logging (no custom bean needed)
- `HealthIndicator` — health checks (no custom bean needed)
- `RequestValidator` — request validation (no custom bean needed)
- `RestApiClient` — REST client with pooling (no custom bean needed)

✅ **SDK3 provides filters automatically:**
- `RequestContextFilter` — correlation ID propagation (auto-registered, no custom bean needed)
- `RequestValidationFilter` — request validation (auto-registered, no custom bean needed)

**Do NOT create custom beans or filters** for these — SDK3's auto-configuration will provide them.

## SDK3 Auto-Configuration & Transitive Dependencies

### What You Get From the 3 Core Dependencies

When you add the 3 core SDK3 modules (request-validator, restapi, meshconnector), the SDK3 BOM automatically provides:

**Module 1: Logging Framework**
- `LogFactory` class for getting loggers (mandatory, replaces SLF4j)
- Pre-configured Log4j2 with async appenders
- MDC (Mapped Diagnostic Context) integration
- `com.barclays.api:bap-bld-lib-logging` (transitive)

**Module 2: Common Patterns**
- Response wrappers and generic types
- Request/response envelopes
- Standard exception types
- `com.barclays.api:bap-bld-lib-common` (transitive)

**Module 3: Payload Handling**
- RestResponse builder pattern
- ResponseHttpStatus enums
- Request/response metadata
- `com.barclays.api:bap-bld-lib-payload` (transitive)

**Module 4: REST Client**
- RestApiClient bean with connection pooling
- HTTP connection management
- Request/response interceptors
- PerfLogger integration
- `com.barclays.api:bap-bld-lib-restclient` (transitive)

**Module 5: Health Checks**
- HealthIndicator beans
- /health and /actuator/health endpoints
- System health monitoring
- `com.barclays.api:bap-bld-lib-health` (transitive)

**Module 6: Request Validation**
- RequestValidator bean
- Request validation against OpenAPI 3.x specs
- RequestValidationFilter (auto-registered)
- `com.barclays.api:bap-bld-lib-validator` (transitive, via request-validator)

**Module 7: Mesh Connector**
- Eureka client integration
- Service mesh communication
- X-MeshToken injection
- `com.barclays.api:bap-bld-lib-meshconnector` (explicit)

### Bean Auto-Registration

Once you create an `ExternalApiInitializer` or `InternalApiInitializer` bean in ApplicationConfig, Spring Boot's auto-configuration chain is triggered:

**Auto-Registered Beans:**
- ✅ LogFactory instance
- ✅ HealthIndicator(s)
- ✅ RequestValidator
- ✅ RestApiClient with connection pooling
- ✅ RequestContextFilter
- ✅ RequestValidationFilter
- ✅ ServiceMeshRequestInterceptor
- ✅ ResponseWrapperFilter

**You DO NOT create these beans** — the SDK3 plugin auto-configuration does it for you.

### Filter Auto-Registration

SDK3 filters are registered automatically if your application includes the SDK3 package in @ComponentScan:

**Auto-Registered Filters:**
- ✅ RequestContextFilter — Correlation ID propagation to MDC
- ✅ RequestValidationFilter — Request validation against spec
- ✅ ServiceMeshInterceptor — X-MeshToken header injection

**Requirement:** `@ComponentScan(basePackages = {"your.package", "com.barclays.api"})`

If @ComponentScan doesn't include "com.barclays.api", filters won't be registered and SDK3 features won't work.

### @ComponentScan is MANDATORY

Your application class MUST include:

```java
@SpringBootApplication
@ComponentScan(basePackages = {"com.acme.orders", "com.barclays.api"})
public class OrderServiceApplication {
    public static void main(String[] args) {
        SpringApplication.run(OrderServiceApplication.class, args);
    }
}
```

**Two basePackages required:**
1. Your application package (e.g., `com.acme.orders`)
2. Barclays SDK3 package: `com.barclays.api`

**Missing @ComponentScan or wrong packages = SDK3 features disabled.**
