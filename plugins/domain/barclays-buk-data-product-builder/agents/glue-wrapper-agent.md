## Single Table Per Invocation (MANDATORY)

This agent processes EXACTLY ONE target table per conversation instance.
The command layer handles multi-table orchestration via Task() spawning.
Do NOT loop through target_tables — you receive ONE table's data only.

## Wrapper.py Generation

Use template: `${CLAUDE_PLUGIN_ROOT}/templates/glue/wrapper_py_per_table.template.py`

**Key rules** (reference only — template is authoritative):
1. DTX framework calls `def main(env, business_date, param):` directly — this IS the entry point
2. `s3_bucket` resolved from `config['environments'][env]['s3_bucket']` at runtime (env-specific bucket stored in config.json)
3. `glue_read_table`, `glue_read_icb_table` are DTX-framework-injected globals (available in module scope at runtime)
4. 4-slot `param`: `param[0]=operation`, `param[1]=table_type (NonTransactional_SCD2 | NonTransactional_SCD1 | Transactional)`, `param[2]=start_date`, `param[3]=end_date`
5. Wrapper extracts ONLY `operation = param.split(',')[0].strip()` for dispatch — passes raw `param` string to transform class
6. Transform normalizes: `self.param = [p.strip() for p in param.split(',')] if isinstance(param, str) else param`
7. `business_date` received as `main()` parameter; falls back to `dc.retrieve_date()` if falsy
8. `config['date_control']['file_path']` updated from resolved `s3_bucket`
8. Import transform classes based on load_type (conditional imports via `{{import_block}}`)
9. **Catch-up mode detection**: After business_date resolution, compare `system_date - business_date` against `config['catch_up_threshold_days']` (default: 1). If gap exceeds threshold AND operation is `day1`/`bau`, set `config['_source_operation_override'] = 'catch_up_mode'`. SourceReader uses `catch_up_mode` filters; TargetWriter unaffected.
10. Dispatch: `day0` → `_transform_day0`; `day1`/`bau` → `_transform_day1`
11. Pass raw `param` string to transform constructor
12. Call `transform.run()` — internally calls `prepare_sources() → transformation() → load()`
13. `dc.update_date_control()` ONLY on success (inside try block; not in finally)

**Conditional Transform Imports** — resolve `{{import_block}}` placeholder based on load_type:

> **`database_name` resolution**: `database_name` = `mapping_parsed.json → target_database` (EXACT value from mapping Excel, no prefix/suffix stripping, no derivation from tenancy Feature Team Name). See `/gen-config` STEP 0.6.

> **`{{table_name}}` resolution**: `{{table_name}}` = `{database_name}_{target_table}` (fully qualified with db prefix). Example: database=`fdp_uk_mortgage_db`, target_table=`mortgage_account` → `{{table_name}}` = `fdp_uk_mortgage_db_mortgage_account`. This MUST match the transform file/class naming convention (see transform-generator-agent.md § "File Naming Convention (CRITICAL)").

- `load_type='Day0'` → `from {{table_name}}_transform_day0 import {{table_name}}_transform_day0`
- `load_type='BAU'` → `from {{table_name}}_transform_day1 import {{table_name}}_transform_day1`
- `load_type='full_then_incremental'` → both import lines

**Reference — config.json structure (read-only context for wrapper alignment):**

**Single-Data-Flow Structure** (`config_single_data_flow.template.json`):
- `database`: target database name
- `tablename`: target table name
- `source.non-transactional{}`: source tables classified as NonTransactional
- `source.transactional{}`: source tables classified as Transactional
- `filters`: organized by load_type (day0/day1/catch_up_mode) and transaction type
- `file_locations`: paths without source_system prefix
- `date_control.filename`: `data/stg/date_control/{{database_name}}/{{table_name}}/date_control.dat`

**Multiple-Data-Flow Structure** (`config_multiple_data_flow.template.json`):
- `source.{{source_system}}.non-transactional{}`: nested by source_system
- `source.{{source_system}}.transactional{}`: nested by source_system
- `filters`: organized by load_type → source_system → transaction_type
- `file_locations`: paths include {{source_system}} prefix

### Per-Source Table Type Grouping (NON-NEGOTIABLE)

**Source tables are placed under their OWN type key, NOT the target table's type.**

Each source table's type is from `session/source_table_metadata.json`:
1. Look up `source_table_type` for each source
2. Place under its classified type (config key uses lowercase-hyphen convention):
   - `"NonTransactional_SCD2"` → `source.non-transactional`
   - `"NonTransactional_SCD1"` → `source.non-transactional-scd1`
   - `"Transactional"` → `source.transactional`
   - `"Unknown"` → should not occur (/classify-sources HALTs and asks user before writing Unknown). If encountered → HALT: "Source table type unresolved for {source_table}. Provide via source_table_metadata.json or explicit invocation context."
3. Ensure filter defaults exist for BOTH types if sources span both

**Filter resolution rule**: if alias key present → use exclusively; if absent → use default.

### Source Column Population (NON-NEGOTIABLE)

Each source table entry's `columns` array MUST be populated with the specific columns read from that source table.

**Source of truth**: `source_columns_per_table` map (passed by command, extracted from `mapping_parsed.json → columns[].source_references[]`).

**Algorithm**:
1. For each source table alias in config.json `source` section:
2. Look up `source_columns_per_table[alias]` → array of column names
3. Set `"columns": [sorted unique column list]`
4. If alias not found in map (should not happen) → set `"columns": []` and log WARNING

**Why populated (not empty)**:
- Empty `columns` causes SourceReader to read ALL columns from the source table
- Populated `columns` enables column pruning at scan time (`.select(columns)`)
- Reduces I/O, memory, and shuffle data proportional to unused columns skipped

**Example**:
```json
"customer_response": {
    "table": "fdp_uk_nps_db_icbg.customer_response",
    "columns": ["active", "customer_response_date", "customer_survey_id", "question_id", "source_system_key"]
}
```

### S3 Path Database Name Rule (NON-NEGOTIABLE)

> **Iceberg suffix rules**: See `database-naming-standards` skill (Iceberg Suffix Convention section).

**Strip `_iceberg` suffix from database name when used in S3 paths.**

**Where to KEEP `_iceberg`** (logical catalog references):
- `config.database` field

**Where to STRIP `_iceberg`** (S3 path components):
- `config.file_locations.*` (flag_indicator, surrogate_key, spark_checkpoint_dir)
- `config.date_control.filename` and `backup_filename`

**Derivation**: `database_name_base = database_name.removesuffix('_iceberg')`

**Common structure** (both templates):
- `crypto` (only when `any_column_crypto_flagged = true`):
  - Per env (dev/uat/prd): `secret_name: sms-crypto-{{tenancy_name}}`, `itsi` from `env_config.{env}.crypto_itsi`, `api_endpoint_url` from `env_config.{env}.crypto_api_endpoint_url`
- `date_columns`: optional list of custom date columns

## Glue Performance — Wrapper.py SparkSession Config Tuning

The wrapper template defines a SparkSession with baseline Spark configs. Adjust based on data volume from domain knowledge:

**`spark.sql.shuffle.partitions`** — template placeholder `{{shuffle_partitions}}`:
- Default: `200`
- Data volume >1TB → `800`; 100GB–1TB → `400`; <1GB → `50`
- No volume signal → `200`

**`spark.sql.autoBroadcastJoinThreshold`** — NOT in template by default:
- If domain knowledge identifies lookup tables <10MB → add `.config("spark.sql.autoBroadcastJoinThreshold", 10485760)`
- If no signal → omit (Spark default applies)

**AQE settings** — enabled in template by default. Do NOT disable unless domain knowledge explicitly requires.

**Iceberg catalog config** — NOT in wrapper (comes from DTXOG SparkConf at runtime). Do NOT duplicate.
