# /gen-driver

Generate the Databricks driver notebook **atomically paired with DDL per target table**. **Databricks only** — refused for Glue.

## CRITICAL: Per-Target-Table Output with Atomic Pairs

This command generates **ONE DRIVER + DDL PAIR PER TARGET TABLE** — NOT a single driver for all tables.

### Atomic Pair Concept

**Driver and DDL are always generated together**:
- Both exist or both are missing — never one without the other
- Ensures schema consistency between DDL and driver implementation
- If generation fails for one, both are rolled back

### Output Format

**Single-target output**:
```
generated/databricks/src/Notebooks/day0/cdp_uk_complaints_db_case_event_dbx/cdp_uk_complaints_db_case_event_dbx_driver.py
```

**Multi-target output** (3 target tables, Day0 + Day1):
```
generated/databricks/src/Notebooks/day0/{target_schema}_{table}/{target_schema}_{table}_driver.py
generated/databricks/src/Notebooks/day1/{target_schema}_{table}/{target_schema}_{table}_driver.py
```

**Multi-source-system output** (2 source systems, Day0 + Day1):
```
generated/databricks/src/Notebooks/day0/{source_system_1}/{target_schema}_{table}/{target_schema}_{table}_driver.py
generated/databricks/src/Notebooks/day0/{source_system_2}/{target_schema}_{table}/{target_schema}_{table}_driver.py
generated/databricks/src/Notebooks/day1/{source_system_1}/{target_schema}_{table}/{target_schema}_{table}_driver.py
generated/databricks/src/Notebooks/day1/{source_system_2}/{target_schema}_{table}/{target_schema}_{table}_driver.py
```

> **NOTE**: config.yml is generated by `/gen-config` (runs before this command). Driver reads the co-located config at runtime but does NOT generate it.

Create directories `generated/databricks/src/Notebooks/{day0|day1}/{target_schema}_{table}/` if they do not exist.
When `data_flow_detection.source_systems` is non-empty (multi-source-system): create `generated/databricks/src/Notebooks/{day0|day1}/{source_system}/{target_schema}_{table}/` instead.

Each driver is **target-table-specific** and contains:
- Config loading from co-located `{target_schema}_{table}_config.yml`
- Airflow business date widget (single widget: `business_date`)
- Transform class instantiation and `transform.run()` execution
- DateControl initialization and advancement
- AuditLogger initialization


- Platform = Databricks (refuse if Glue)

## STEP 0.15 — Multi-Source-System Awareness

Read `session_state.data_flow_detection`:

- **`source_systems` is non-empty** (i.e., `data_flow_detection.source_systems[]` has 1 or more entries — even a single entry like `["trmph"]` qualifies): This target uses source-system-scoped artifacts. Execute STEP 2+ in a **loop over source_systems** in `session_state.data_flow_detection.source_systems[]`. For each source_system:
  - Output path: `generated/databricks/src/Notebooks/{day}/{source_system}/{target_schema}_{table}/{target_schema}_{table}_driver.py`
  - Each driver's `%run` references its co-located transform: `# MAGIC %run ./{target_schema}_{table}_transform`
  - Each driver's config path resolves to its co-located config: `{target_schema}_{table}_config.yml` (same directory)
  - `process_name` in driver: `{target_schema}_{table}_{source_system}` (for independent DateControl)
  - Directory creation: `generated/databricks/src/Notebooks/{day0|day1}/{source_system}/{target_schema}_{table}/`

- **`artifact_mode == "combined"`** or **`source_systems` is empty**: Standard single-flow generation (unchanged — one driver per target table per day).

## Behaviour

### STEP 1 — Platform Check

If platform = Glue: REFUSE with:
> "driver.py is Databricks only. For AWS Glue, use /gen-wrapper to generate wrapper.py."

### STEP 2 — Generate driver notebook

Delegate to `databricks-artefact-agent` (using the Agent tool) with `artefact_scope: "driver"`. Rules:

**Notebook structure** (Databricks notebook — `.py` file with `# Databricks notebook source` header):
- Three widgets (all from template — do NOT add others):
  - `dbutils.widgets.text("environment", "dev")` — DABs deployment target
  - `dbutils.widgets.text("business_date", "")` — Airflow override
  - `dbutils.widgets.text("log_level", "INFO")` — Logging verbosity
- Config loaded from co-located `config.yml` (all parameters from config, NOT widgets)
- `# MAGIC %run ./{target_schema}_{table_name}_transform` to import transform class
- Flat notebook cells (no `def main()` / `if __name__`)

**Foundation imports** (submodule paths):
```python
from databricks_foundation.core.date_control import DateControl
from databricks_foundation.logger.audit_logger import AuditLogger
```

**Config loading**:
```python
_config_path = f"/Workspace{_notebook_dir}/{target_schema}_{table_name}_config.yml"
with open(_config_path, "r") as f:
    config = yaml.safe_load(f)
```

**Business date resolution** (Airflow override → DateControl fallback):
```python
_airflow_bus_dt = dbutils.widgets.get("business_date").strip()
if _airflow_bus_dt:
    curr_bus_dt = _airflow_bus_dt
else:
    dates = dc.get_business_dates(date_control_table=..., process_name=...)
    curr_bus_dt = dates["curr_bus_dt"]
```

**Catch-up mode detection** (after business_date resolution, before transform instantiation):
```python
_catch_up_threshold = config.get("pipeline", {}).get("catch_up_threshold_days", 1)
_system_date = date.today()
_bus_date = datetime.strptime(curr_bus_dt, "%Y-%m-%d").date()
_date_gap_days = (_system_date - _bus_date).days

if load_type.lower() in ("bau", "day1") and _date_gap_days > _catch_up_threshold:
    config["_source_operation_override"] = "catch_up_mode"
```

When triggered, SourceReader uses `catch_up_mode` filters (wider temporal window) instead of `day1` filters. TargetWriter write strategy is unaffected — it still uses the original operation (`bau`/`day1`) for CDC merge or append logic.

**Transform class instantiation**:
```python
transform = {target_schema}_{table_name}_transform(
    spark=spark, config=config, curr_bus_dt=curr_bus_dt, audit=audit
)
transform.run()
```

**Date control advancement** (only on success):
```python
dc.update_date_control(table_nm=date_ctrl_table, process_name=process_name)
```

**Rolling deletion**: `config['rolling_deletion']` is handled entirely inside `TargetWriter._rolling_delete()`. The driver passes the full config dict to the transform constructor — no driver-level rolling deletion code is needed.

### STEP 2.5 — Config/Driver Environment Consistency Check (BLOCKING)

After driver generation, verify that the driver's `SUPPORTED_ENVS` matches the co-located config.yml's `environments` keys:

1. **Read co-located config.yml:**
   - Path: `generated/databricks/src/Notebooks/{day0|day1}/{target_schema}_{table}/{target_schema}_{table}_config.yml`
   - Multi-source-system path: `generated/databricks/src/Notebooks/{day0|day1}/{source_system}/{target_schema}_{table}/{target_schema}_{table}_config.yml`
   - Extract: `list(config["environments"].keys())` → `config_envs`

2. **Read generated driver.py:**
   - Extract: `SUPPORTED_ENVS` tuple from the generated driver file
   - Parse the tuple values → `driver_envs`

3. **Compare:**
   - If `set(config_envs) == set(driver_envs)` → PASS, continue to STEP 3
   - If mismatch detected:
     - **Auto-fix:** Override `SUPPORTED_ENVS` in the generated driver to: `SUPPORTED_ENVS = tuple(config_envs)`
     - Log: `[ENV-SYNC] Fixed SUPPORTED_ENVS mismatch — config has {config_envs}, driver had {driver_envs}. Overridden to match config.`
     - Write corrected driver back to disk

4. **HALT condition:**
   - If config.yml has environments NOT in the valid set (`dev`, `preprd`, `prd`, `uat`) → HALT:
     ```
     ⛔ HALT: config.yml contains invalid environment key(s): {invalid_keys}
        Valid keys: dev, preprd, prd, uat
        Re-run /gen-config to fix environment resolution.
     ```


### Session State Updates

After generation: `table_status[table_name].driver_generated = true`

### Atomic Pair Enforcement

- driver + DDL must be generated together
- Verification: After generation, check both files exist
- If DDL missing: set driver_generated = false, mark failed
