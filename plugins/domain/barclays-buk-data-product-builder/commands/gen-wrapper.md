# /gen-wrapper

Generate `wrapper.py` per target table. **AWS Glue only** — refused for Databricks.

> **NOTE**: `config.json` is generated by `/gen-config` (runs before this command and before `/gen-transform`). This command generates the wrapper ONLY — config must already exist.

## ⚠️ CRITICAL: Per-Target-Table Output

This command generates **ONE WRAPPER PER TARGET TABLE** — NOT a single wrapper for all tables.

### Prerequisites

- Config generated (`{db}_{target_table}_config.json` exists — generated by `/gen-config`)
- Transform generated (`{db}_{target_table}_transform_day0.py` and/or `_day1.py` exists)

### Output Format

**Single-target output**:
```
generated/glue/wrapper/fdp_uk_mortgage_db_account_wm_wrapper.py
```

**Multi-target output** (3 target tables):
```
generated/glue/wrapper/fdp_uk_mortgage_db_account_wm_wrapper.py
generated/glue/wrapper/fdp_uk_mortgage_db_rates_fees_wrapper.py
generated/glue/wrapper/fdp_uk_mortgage_db_mortgage_detail_wrapper.py
```

> config.json files are already present in `generated/glue/wrapper/` (generated earlier by `/gen-config`).

**Multi-source-system output** (when `data_flow_detection.source_systems` is non-empty — one wrapper per source_system):
```
generated/glue/wrapper/fdp_uk_mortgage_db_account_wm_ilp_wrapper.py
generated/glue/wrapper/fdp_uk_mortgage_db_account_wm_reference_data_wrapper.py
```

Create directory `generated/glue/wrapper/` if it does not exist.

### Multi-Source-System Awareness

Read `session_state.data_flow_detection`:

- **`source_systems` is non-empty**: Generate N wrappers (one per source_system in `session_state.data_flow_detection.source_systems[]`):
  - Output: `generated/glue/wrapper/{db}_{table}_{source_system}_wrapper.py`
  - Each wrapper reads its co-located config: `{db}_{table}_{source_system}_config.json`
  - Each wrapper imports its source_system-specific transforms: `{db}_{table}_{source_system}_transform_{day}`
  - Transform class naming: `{db}_{table}_{source_system}_transform_{day}`
- **`"combined"` or `source_systems` is empty**: Unchanged (one wrapper per target table).

### Conditional Transform Imports

The wrapper imports **ONLY the transform files that were actually generated for this table**:

> **Load type terminology:** See `${CLAUDE_PLUGIN_ROOT}/agents/refs/load-type-terminology.md`

- **Load type = 'Day0'** → imports `{{db}}_{{target_table}}_transform_day0` only
- **Load type = 'BAU'** → imports `{{db}}_{{target_table}}_transform_day1` only
- **Load type = 'full_then_incremental'** → imports both `_day0` and `_day1`

This means each target table's wrapper is customized for its specific load pattern. The wrapper doesn't import transform files that weren't generated.

### Example: Multi-Target with Mixed Load Types

**Input** (3 target tables, different load types, db = fdp_uk_mortgage_db):
```
account_wm: load_type = 'BAU'
rates_fees: load_type = 'Day0'
mortgage_detail: load_type = 'full_then_incremental'
```

**Wrapper Imports**:
```
fdp_uk_mortgage_db_account_wm_wrapper.py:
  imports fdp_uk_mortgage_db_account_wm_transform_day1 only

fdp_uk_mortgage_db_rates_fees_wrapper.py:
  imports fdp_uk_mortgage_db_rates_fees_transform_day0 only

fdp_uk_mortgage_db_mortgage_detail_wrapper.py:
  imports fdp_uk_mortgage_db_mortgage_detail_transform_day0 AND fdp_uk_mortgage_db_mortgage_detail_transform_day1
```

## Mapping Input Projection (Context Efficiency)

When passing `mapping_parsed.json` data to the `glue-wrapper-agent`, include ONLY these fields per target table:
- `target_table`, `target_database`
- `source_tables[]` → `database`, `table`, `alias`, `type`
- `source_columns_per_table` → grouped map: `{alias: [col1, col2, ...]}` extracted from `mapping_parsed.json → columns[].source_references[]`
- `load_type`
- `crypto_flagged` (boolean)

**Omit**: `transformation_logic`, `descriptions`, full column definitions (datatype, nullable, description per column)

This adds `source_columns_per_table` — a compact grouped map (~200–400 tokens for typical mappings) that provides exactly the column names needed without passing full column definitions.

**Extraction algorithm** (executed by command orchestrator before invoking agent):
```python
source_columns_per_table = {}
for col in mapping_parsed['columns']:
    for sr in col['source_references']:
        alias = sr['source_table']
        column = sr['source_column']
        source_columns_per_table.setdefault(alias, set()).add(column)
source_columns_per_table = {k: sorted(v) for k, v in source_columns_per_table.items()}
```

## Behaviour — Multi-Table Batching (Phase B2)

**NEW**: This command now supports **multiple tables in parallel batches**.

### Multi-Table Execution Flow

```
Load target_tables from session state (array)
├─→ If length = 1: Single-table mode (backward compatible)
├─→ If length > 1: Multi-table batch mode
│    ├─→ Batch into groups of 3–5 tables
│    ├─→ Launch parallel glue-wrapper-agents (background tasks)
│    ├─→ Wait for all tasks to complete (wrapper + config atomic per table)
│    ├─→ Merge results into single session state
│    └─→ Verify all tables generated successfully
└─→ Write consolidated audit log entry
```

### Parallel Batching Configuration

```
Default batch_size = 3 (can be overridden in session_state)
Max concurrent tasks = min(16, cpu_cores - 2)
Wait strategy = barrier (wait for all in batch before next batch)
```

## Behaviour — Single & Multi-Table Logic

Both files generated atomically — no gate required. Delegate to `glue-wrapper-agent` (using the Agent tool).

### wrapper.py Rules

- DTX framework calls `def main(env, business_date, param):` directly — this IS the entry point
- 4-slot comma-delimited `param`:
  - `param[0]` = operation (`day0` | `day1` | `bau`)
  - `param[1]` = table_type (`Transactional` | `NonTransactional`)
  - `param[2]` = start_date (YYYYMMDD)
  - `param[3]` = end_date (YYYYMMDD)
- Resolve `s3_bucket` from `config['environments'][env]['s3_bucket']` (env-specific, stored in config.json)
- Set `config['s3_bucket']` and `config['date_control']['file_path']` from resolved `s3_bucket`
- `business_date` Lambda arg overrides `dc.retrieve_date()`
- Extract only `operation = param.split(',')[0].strip()` for dispatch
  - `table_type`, `start_date`, `end_date` are NOT extracted in wrapper — the transform class splits the raw param string and extracts them internally
- Import both transform classes:
  - `from {db}_{table_name}_transform_day0 import {db}_{table_name}_transform_day0`
  - `from {db}_{table_name}_transform_day1 import {db}_{table_name}_transform_day1`
- **Catch-up mode detection** (after business_date resolution, before dispatch):
  - Read `config.get('catch_up_threshold_days', 1)`
  - If `operation in ('day1', 'bau')` AND `(system_date - business_date).days > threshold`:
    - Set `config['_source_operation_override'] = 'catch_up_mode'`
    - SourceReader uses `catch_up_mode` filters (wider temporal window); TargetWriter unaffected
- Dispatch: `day0` → instantiate `_transform_day0`; `day1`/`bau` → `_transform_day1`
- Pass raw `param` string to transform constructor (transform splits and extracts `table_type`, `start_date`, `end_date` internally)
- Call `transform.run()` (which calls prepare_sources → transformation → load internally)
- Call `dc.update_date_control()` **only on success** (inside try block; not in finally)
- **Rolling deletion**: `config['rolling_deletion']` is handled entirely inside `TargetWriter._rolling_delete()`. The wrapper passes the full config dict — no wrapper-level rolling deletion code is needed.

## Batching Execution (Phase B2)

### Algorithm: Batch Processing with Parallel Launch

```
Step A: Load Configuration
  session = load_session_state()
  target_tables = session.target_tables (array)
  batch_size = session.batch_size or 3 (default)
  
Step B: Determine Mode
  if len(target_tables) == 1:
    MODE = "single-table" (backward compatible)
  else:
    MODE = "batch-parallel"

Step C: Single-Table Mode (unchanged)
  if MODE == "single-table":
    Invoke glue-wrapper-agent (using the Agent tool) for wrapper + config generation
    Write single wrapper.py + config.json pair
    Return

Step D: Batch-Parallel Mode (NEW)
  if MODE == "batch-parallel":
    batches = []
    for i in range(0, len(target_tables), batch_size):
      batch = target_tables[i:i+batch_size]
      batches.append(batch)
    
    all_results = []
    for batch_num, batch in enumerate(batches):
      tasks = []
      for table_index, table in enumerate(batch):
        task = Task(
          agent="glue-wrapper-agent",
          prompt=f"Generate wrapper + config for table {table.name}",
          label=f"wrapper_batch{batch_num}_table{table_index}",
          run_in_background=True
        )
        tasks.append(task)
      
      # Wait for all tasks in batch to complete (barrier)
      for task in tasks:
        result = task.wait()  # blocking
        all_results.append(result)
    
    # Merge results
    merged = merge_wrapper_results(all_results)
    
    # Update session state
    session.target_tables.all_wrappers_generated = True
    session.batch_results = merged.batch_results
    session.performance_metrics = {
      "total_time_ms": merged.total_time_ms,
      "per_table_avg_ms": merged.per_table_avg_ms,
      "speedup": merged.speedup_vs_sequential
    }
    save_session_state(session)
    
    # Log aggregated result
    log_audit_entry({
      "event": "wrapper_generation_batch_complete",
      "tables": len(all_results),
      "time_ms": merged.total_time_ms,
      "status": "success"
    })
```

### Result Merging Logic

```
For each wrapper.py + config.json pair generated:
  Load file metadata
  Verify both files present (atomic pair)
  Collect metadata (table_name, param_slots, crypto_secrets)
  
Aggregate:
  total_tables = count of successful wrapper+config pairs
  total_time = sum of all batch times
  per_table_avg = total_time / total_tables
  speedup = (expected_sequential_time) / (actual_parallel_time)
```

## STEP FINAL.1 — Contract Reconciliation (Non-Blocking)

After syntax validation, verify that generated artefacts (wrapper, transform, config) respect the runtime API contracts of the generic components (`reader.py`, `writer.py`, `date_control.py`).

**Validator:** `${CLAUDE_PLUGIN_ROOT}/validators/contract-reconciliation-validator.md`

### Pre-conditions

- STEP FINAL (syntax check) has completed (pass or fail — contract check runs regardless)
- Generated wrapper, transform, and config files exist for at least one target table

### Execution

For each target table, run all 7 checks from the contract-reconciliation-validator:

| Check | What it verifies |
|-------|-----------------|
| C1 — API return shape | `retrieve_date()` tuple unpacking in wrapper |
| C2 — Config value safety | `int()` won't crash on empty workday_number fields |
| C3 — Audit column type | `active` literal type consistent (writer SQL vs transform F.lit) |
| C4 — Day0/Day1 audit contract | Correct audit columns present/absent per operation + table_type |
| C5 — Constructor signature | Wrapper/transform pass correct kwargs to Reader/Writer/Transform |
| C6 — CDC PK completeness | `cdc.primary_key_cols` non-empty and columns exist in transform output |
| C7 — date_control config | All 8 required date_control keys present in config |

### If ALL checks pass:

```
✅ Contract reconciliation passed ({N} tables, 7 checks each)
```
Set `session_state.contract_reconciliation_result = "passed"`. Set `session_state.contract_reconciliation_violations = null`.

### If ANY check fails:

```
⚠️ Contract violations detected (non-blocking):
   • {check_id}: {description} in {file_path}
   ...
```
Set `session_state.contract_reconciliation_result = "failed"`. Set `session_state.contract_reconciliation_violations = [{...}]`.

### Self-Heal Retry

On violation:
1. Re-invoke the responsible agent with the violation list and fix guidance (up to 2 retries)
2. After 2 retries: mark files as `DRAFT_UNVALIDATED`

Set `session_state.contract_reconciliation_retries = {N}`.

Log to `session/audit_log.jsonl`: `[CONTRACT-CHECK] {result} — {N} tables checked, {M} violations`.

**CRITICAL:** Contract failures do NOT halt the generation pipeline. They are reported for awareness and enforced at `/push` time (Condition 5: `contract_reconciliation_result != "passed"` → refuse).

## Failure Modes

- Platform = Databricks → REFUSE with: "wrapper.py and config.json are AWS Glue / DTX-BYOC only."
- Transform not yet generated → warn; proceed with placeholder transform reference
- ⛔ **{{sms_secret_name}} cannot be resolved** (invalid tenancy) → HALT (fail fast)
- **Batch mode: One table fails → SKIP and continue with others (fault-tolerant)**
- **Batch mode: Partial atomic pair → Mark as DRAFT_UNVALIDATED; log which tables failed**
- **Batch mode: Atomic pair incomplete → Mark as failed; both wrapper and config must be present**
