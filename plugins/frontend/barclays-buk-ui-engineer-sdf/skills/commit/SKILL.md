# Commit and Gate Patterns

> **Scope:** buk-ui-engineer-sdf task agents only
> **Owner:** BUK Retail CAPL

---

## 1. TypeScript Compilation Gate

Run this gate after every code generation step before committing.

### 1.1 Run the gate

```bash
cd "{PROJECT_PATH}" && node_modules/.bin/tsc --noEmit 2>&1
```

Capture the full output. Then separate errors into two buckets:
- **Generated file errors** — errors in files written by this agent (under `src/screens/{ComponentName}/`)
- **Pre-existing errors** — errors in any other file (`mockBridge/`, `src/components/`, `node_modules/`, spec files, etc.)

The gate passes if **generated file errors = 0**, regardless of pre-existing errors. Pre-existing errors must be reported in `flags` but do not block generation.

### 1.2 On failure — fix and retry

If generated file errors > 0:

1. Read the error lines for the generated files only
2. Fix the specific TypeScript errors — do not rewrite unrelated code
3. Re-run the gate
4. Maximum **3 retries** for standard agents; maximum **2 retries** for stub agents

**NEVER filter tsc output to silently ignore errors in generated files.** Separating pre-existing from generated errors is allowed and correct — but errors in generated files must be fixed.

**NEVER filter tsc output to declare success.** Running `tsc --noEmit 2>&1 | grep "myFile"` and finding no matches does NOT mean the gate passed — the gate is the exit code. If exit code != 0, the gate failed. Do not grep, do not cherry-pick, do not proceed.

**NEVER rewrite or patch `tsconfig.json`, `node_modules`, or third-party type definitions** to make the gate pass. If errors come from `node_modules`, the project already has a broken setup — report it as a pre-existing environment problem and stop. Do not modify `skipLibCheck`, `exclude`, or any tsconfig setting to silence errors you didn't introduce.

### 1.3 On persistent failure

If the gate is still failing after the maximum retries, or if errors come from `node_modules` / third-party types that cannot be fixed:

```bash
log "[ERROR] tsc gate failed — stopping"
```

**Stop. Do not commit. Report the full unfiltered error output to the user**, including:
- The exact tsc exit code
- All error lines (not just errors in generated files)
- Whether the errors are pre-existing (in node_modules) or introduced by the generated code
- What the user needs to do to fix the environment before re-running

### 1.4 On success

```bash
log "[tsc] gate passed"
```

Proceed to Section 2.

## 2. ESLint Gate

Run this gate after the TypeScript compilation gate passes and before staging any files.

### 2.1 Run the gate

```bash
cd "{PROJECT_PATH}" && npx eslint {FILES_WRITTEN_BY_THIS_TASK} 2>&1
```

### 2.2 On failure — fix and retry

If exit code != 0:

1. Read the full lint output
2. Fix only the lint errors in the files generated by the current task — do not touch unrelated files
3. Re-run the gate
4. Maximum **3 retries**

### 2.3 On persistent failure

If the gate is still failing after 3 retries:

```bash
log "[ERROR] eslint gate failed after 3 retries — stopping"
```

Stop. Report the errors to the user. Do not commit.

### 2.4 On success

```bash
log "[eslint] gate passed"
```

Proceed to Section 3.

## 3. Conventional Commit

### 3.1 Stage files

Stage only the files written or modified by the current task. Never `git add .` or `git add -A`.

```bash
cd "{PROJECT_PATH}" && git add {FILES_WRITTEN_BY_THIS_TASK}
```

### 3.2 Check for staged changes

```bash
git diff --cached --quiet && echo "NO_CHANGES" || echo "HAS_CHANGES"
```

If `NO_CHANGES` — skip the commit entirely and note it in the report.

### 3.3 Commit format

```bash
git commit -m "$(cat <<'EOF'
{type}({JIRA_ID}): {description}

{optional body — one or two sentences if the change needs context}

Co-Authored-By: Claude Sonnet <noreply@anthropic.com>
EOF
)"
```

**Commit type mapping:**

| Task agent | type |
|---|---|
| `screen-composer-agent` | `feat` |
| `api-agent` | `feat` |
| `stub-agent` | `chore` |
| `test-agent` | `test` |
| `mutation-agent` | `test` |

**Description:** imperative, present tense, lowercase, no trailing period. Maximum 72 characters on the first line (type + scope + description combined).

### 3.4 Examples

```bash
# screen-composer-agent
git commit -m "feat(UCG-1234): compose Blueprint screen components"

# api-agent
git commit -m "feat(UCG-1234): wire RTK Query API layer"

# stub-agent
git commit -m "chore(UCG-1234): add visual flow stubs"

# test-agent
git commit -m "test(UCG-1234): add platform-split jest specs"

# mutation-agent (new config)
git commit -m "test(UCG-1234): scaffold Stryker mutation config"
```

## 4. Log Conventions

All agents share the same log file at `{PROJECT_PATH}/logs/ui-engineer-sdf.log`.

### 4.1 Initialise log function

Each agent declares its own log function at the start. Replace `{AGENT_NAME}` with the agent's `name` from its front-matter.

```bash
log() { echo "[$(date '+%d/%m/%y %H:%M:%S')] [AGENT:{AGENT_NAME}] $1" >> "${PROJECT_PATH}/logs/ui-engineer-sdf.log"; }
```

### 4.2 Standard log events

```bash
log "[START] jira={JIRA_ID} task={TASK_DESCRIPTION}"
log "[INFO] {step description}"
log "[tsc] gate passed"
log "[eslint] gate passed"
log "[ERROR] {description}"
log "[COMPLETE] {summary}"
```

### 4.3 Initialise log directory

```bash
mkdir -p "{PROJECT_PATH}/logs"
```

Always run this before the first `log` call.
