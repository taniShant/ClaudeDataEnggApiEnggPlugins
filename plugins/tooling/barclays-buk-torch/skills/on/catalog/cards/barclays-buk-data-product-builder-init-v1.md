## Description

Initialize DE session from mapping Excel — invoke when user provides a mapping document or says start/begin pipeline

## When to use

Use when starting a new data product pipeline from an Excel mapping document; this is the first and mandatory command in the data product builder workflow. NOT for modifying existing pipelines (invoke gen-transform, gen-dag, gen-ddl, or other gen-* commands directly) and NOT for data modelling (use dm-model). NOT required when resuming an interrupted session — use /resume instead.

## Inputs

- `<excel_path>` (required) — absolute or relative path to the mapping Excel (`.xlsx`) file provided by the data engineering team; this is the single authoritative input that drives all downstream artefact generation
- `--platform <glue|databricks>` (optional; required when `--full-automation` is set) — target compute platform: `glue` for AWS Glue (DTX/DTXOG framework producing wrapper.py, dtxog config, Feedback Mechanism, Mesh JSON) or `databricks` for Databricks BUK CDAO standard PySpark scripts (transform.py, driver.py, Iceberg DDL); if omitted the command prompts the user interactively (Gate G1)
- `--domain-knowledge <path>` (optional) — path to a domain-specific knowledge `.md` file; overrides auto-discovery from the plugin installation directory; loaded immediately if provided
- `--full-automation` (optional flag) — enables full-automation mode: auto-decision-agent resolves ambiguities autonomously when evidence is sufficient and asks the user only when confidence is insufficient; requires `--platform`

## Preconditions

- `barclays-buk-data-product-builder` plugin installed
- A valid `.xlsx` mapping document must exist and be readable at the path provided; the file is the sole authoritative source for pipeline targets — the filename must NOT be used to infer data product type, tenancy, or domain
- `session/` directory must be writable (session state and audit log are written here)
- If `--platform glue` is selected: AWS Glue tenancy must be configured in the active project (validated downstream during parse-mapping)
- If `--platform databricks` is selected: Databricks tenancy must be configured in the active project (validated downstream during parse-mapping)
- If `--full-automation`: `--platform` must also be provided; haiku-class models are not recommended (sonnet-default or higher required for reliable multi-step JSON write-verify and conditional branching)

## Expected outputs

- `session/session_state.json` — initialised session record containing: `session_id` (timestamp-based, e.g. `de_20260603_143022`), `created_at`, `mapping_excel_path`, `platform` (set or null pending Gate G1), `domain_knowledge_path`, `domain_knowledge_text` (null at this stage — populated by parse-mapping), `gates_resolved`, `open_placeholders`, `auto_chain` (populated when `--full-automation` is set), `python_path`, `python_version`
- `session/audit_log.jsonl` — structured audit entry recording session initialisation event, platform validation outcome, stale session detection, Python runtime detection, and (if `--full-automation`) auto-chain initialisation
- Platform routing decision communicated to the user: `glue` or `databricks` (confirmed or deferred to Gate G1 interactive prompt)
- Ready state: session is prepared for the next command (`/parse-mapping`) which reads the Excel, resolves data product type (FDP/CDP/BDP from target database prefix), and resolves tenancy; no artefacts are generated by `/init` itself

## Exclusions

- Does not generate any pipeline artefacts (wrapper.py, transform.py, DDL, etc.) — artefact generation begins with gen-* commands after `/parse-mapping` and intent identification complete
- Does not infer or display data product type (FDP/CDP/BDP) — this is resolved exclusively during `/parse-mapping` by reading the `target_database` prefix from the Excel; the Excel filename is never a valid inference source
- Does not infer or display tenancy — tenancy is resolved during `/parse-mapping` Gate G0.5 via the tenancy registry skill
- Does not replace `/resume` for continuing an interrupted session — if `session/session_state.json` already exists for the same mapping, the user should use `/resume`; `/init` will warn before overwriting
- Does not execute any gen-* pipeline steps even in `--full-automation` mode — Phase A (Discovery) dispatch is triggered only after all `/init` steps complete and the main conversation reads `init-full-automation.md`
- Does not perform data modelling — for business requirements → formal data model use `dm-model`

## Verification

After running `/init`, confirm `session/session_state.json` exists and the `session_id` field matches the value displayed in the success output. Verify `mapping_excel_path` reflects the path provided. If `--platform` was supplied, confirm `platform` is set and `"G1"` appears in `gates_resolved`; if omitted, confirm `platform` is null and the Gate G1 prompt was presented. Check `session/audit_log.jsonl` for an `init_session_write` event. For `--full-automation` runs: confirm `auto_chain.enabled` is `true` and `auto_chain.chain_mode` is `true` in session state, and that an `auto_chain_initialized` audit entry is present. The next command to run is `/parse-mapping`.
